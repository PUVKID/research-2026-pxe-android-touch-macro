# 17차 화면 인식 복구와 자동 스크롤 거리 조정

확인일: 2026-11-02. 사용자 요구는 화면 인식 중단·긴 응답으로 인한 중단을 줄이고, 글자가 없을 때 위로 쓸어올려 목록을 내리는 자동 스크롤 거리를 이전의 절반으로 만드는 것입니다. 16차 소스와 납품 APK는 읽기 전용으로 보존하며 17차에만 변경합니다.

## 확인한 원인과 근거 수준

16차 `foregroundPackage`의 단일 창 조회는 1.5초 응답 제한을 넘으면 실행 전체에 치명 예외를 전달합니다. `QueryLane`의 이전 조회가 아직 끝나지 않은 경우도 같은 종료 경로입니다. OCR 자체의 8초 캡처·12초 인식 지연은 이미 복구하지만, 이 창 조회의 지연과 실제 ML Kit Task 실패·취소는 복구되지 않습니다. 이는 코드 조사와 통제 재현 대상으로 확인한 경로이며, 사용자의 과거 실제 오류 로그를 확보한 것은 아닙니다.

`onInterrupt`는 Android 공식 문서에서 접근성 피드백 중단 콜백이며, 서비스 연결 해제는 `onUnbind`/`onDestroy`로 별도 관리합니다. 연결이 유효한 피드백 중단이 실행 전체를 정지시키는 기존 동작을 분리합니다. 이미 전달한 제스처의 완료·취소를 임의 성공 또는 자동 재시도로 바꾸지 않습니다.

## 변경 계약

- 창 조회의 일시 시간초과와 진행 중 조회는 한 개의 기존 QueryLane을 유지한 채 무터치 복구 대기로 처리합니다. 끝나지 않은 조회 뒤에 작업을 쌓지 않습니다. 늦게 돌아온 이전 결과는 버리고 새 창 조회로 대상을 확인합니다. 복구 이전 화면의 좌표와 부재 관측은 폐기합니다.
- 명시한 화면 정보 방식은 일시 노드 조회 지연 뒤에도 OCR을 사용하지 않습니다. 자동 방식은 기존 한 번의 OCR 전환 정책을 유지합니다. 권한 오류·잘못된 입력·기타 확인되지 않은 실패를 임의 일시 오류로 분류하지 않습니다.
- ML Kit의 `UNAVAILABLE(14)`와 `DEADLINE_EXCEEDED(4)`, 실제 완료된 취소 Task만 새 캡처로 재시도합니다. 후퇴는 0.25/0.5/1/최대2초이며 중단·일시정지·전체 실행 기한을 계속 확인합니다. `INTERNAL(13)`, 권한 없음, 잘못된 입력, 미지원 등은 종료 이유를 명확히 유지합니다. 완료 전 비트맵 해제나 미완료 Task 뒤의 병렬 인식은 추가하지 않습니다.
- 목록의 `SCROLL_DOWN`과 글자 동작의 `SCROLL_RETRY`는 화면 높이 75%→30%(거리45%)에서 75%→52.5%(거리22.5%)로 바꿉니다. 아래로 당겨 새로고침, 사용자가 등록·녹화한 수동 스와이프 좌표와 시간은 보존합니다. 자동 스크롤 좌표는 기존 저장 JSON에 들어 있지 않아 기존 프로필에도 적용됩니다. 실제 콘텐츠 이동량은 대상 앱의 스크롤·관성 처리에 따라 달라집니다.
- 정상 프레임에서 글자가 없는 경우의 유한 `timeout`과 실패 정책은 그대로입니다. 화면 자체를 읽지 못한 일시 인프라 실패는 글자 없음으로 취급하지 않으므로 뒤로가기·스크롤·중복 차단 해제를 실행하지 않습니다. 이 복구 대기 중에도 매크로/탐지의 명시한 전체 최대 실행 시간과 사용자의 정지는 강제합니다. 저장값을 자동으로 무제한으로 바꾸지 않습니다.
- 앱 ID·서명·설정 형식·1~6순위·15회 기본 반복·진입/복귀·중복 방지·단축창·디자인·글꼴을 유지합니다. 새 옵션을 불필요하게 늘리지 않습니다.

## 재현과 검증 계획

제품 엔진 변경 전에 새 순수 스크롤 검사에서 예상 52.5%와 실제 30%의 차이를 재현했습니다. 새 소유 PXE17 Android31 AVD(1080×2280/420dpi·CPU4·RAM2048·SwiftShader)에서 창 조회 지연·노드 조회 지연·피드백 중단·일시 Task 실패/취소와 실제 스와이프 두 경로를 제어 재현합니다. 사용자 블루스택·게임·개인 프로필은 조작하지 않습니다.

이전 검사의 종료 기대값 중 창/노드 지연의 정지 및 45% 자동 스크롤만 새 요구에 맞게 명시 개정합니다. 단일 조회·OCR 미호출·무터치·정지1초·전체 최대 시간·권한 오류·수동 스와이프·정상 유한 부재의 기대값은 유지합니다. 기존 필수52, 추가 인식12, 적응 실행25의 기기 회귀와 새 집중 검사를 구분합니다. 단위·lint·엄격 UTF-8·두 APK 서명/ABI/압축·16차140개 보존·실제16→17 업데이트를 확인합니다. 구현자와 다른 verifier가 최종 소스와 납품본을 독립 검사합니다.
