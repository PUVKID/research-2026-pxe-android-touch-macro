# 15차 인식 지연과 설정 단순화 명세 및 계획

확인일: 2026-10-28. 요청: 블루스택의 화면 정보/보안 안내 혼동, 지연과 정확도 문제를 조사해 새 APK로 만들고 내부 설정을 간결하게 한다. 14차는 완료 상태이며 15차는 새 사용자 요청이다. 과거 실패 및 14차 원본은 보존한다.

## 확인된 원인과 한계
- 목록 탐지 WatchRule.source, 개별 Step.source, 글자 탭 word_source는 별도다. ACCESS는 OCR을 호출하지 않지만 실행 매크로에는 기존 AUTO/OCR 단계가 남을 수 있다.
- CapturePacer는 응답 후 기본 2초이며 간격 거절 후 최대 12초까지 늘어나고 성공 시 회복하지 않는다. 목록 루프에도 최대 2초 대기가 있다.
- OCR은 전체 화면을 처리한 다음 영역을 필터링한다. 영역 자르기는 캐시/절대 좌표/원본 수명을 함께 검증해야 한다.
- 대상 앱이 접근성 글자를 제공하지 않거나 OS가 캡처를 막으면 인식 가능성을 보장할 수 없다. 보안 제한을 우회하거나 못 읽은 좌표를 누르지 않는다.

## 성공 조건
- 엄격 화면 정보 방식에서는 OCR을 호출하지 않는다. 실패 안내는 실제 단계/인식 방식/원인을 구분한다.
- 간격 오류 대응은 제한된 후퇴와 성공 시 회복을 사용한다. 취소/일시정지/대상 앱 경계/단일 OCR 작업과 비트맵 수명은 유지한다.
- 실제 ROI 처리는 좌표 매핑과 같은 순회의 우선순위 캐시 재사용을 보존하는 경우만 도입한다. 실제 확인하지 않은 속도 개선 수치를 제시하지 않는다.
- 목록 및 글자 동작의 방식 선택을 기본에 표시한다. 목록 설정은 글자/방식/매크로/반복/새로고침/완료 후 대기를 기본에, 추가 시간/비교/좌표/분기/재시도는 접는다.
- 기존 5단계 안내 및 저장, 1~6순위, 반복, 중복 방지, 대기/중단과 모든 기존 기능을 유지한다. 일괄 인식 방식 변경은 이번에 추가하지 않으며 적용 범위를 설명한다.
- 글자 동작 편집은 방식과 무한/유한 대기를 쉽게 설정하며 고급 값도 편집/저장 가능하다. PXE 이름/라이트다크/나눔고딕 Bold/48dp 조작 영역 유지.
- 기존 검사 단언을 약화하지 않는다. 새 동작은 먼저 실패를 재현하고 수정한다. 14→15 실제 업데이트 설정 보존, 기존 필수 46개 및 작은 화면 UI6, 새 집중 검사, 빌드/단위/린트/UTF-8/서명/ABI/원본 보존을 확인한다.

## 역할과 순서
1. 부모: 지침 및 원본/도구 확인, 명세, 빌드 연결과 소유 장치, 버전/빌드 검사 도구 업데이트, 이력 기록.
2. 엔진 deep: MacroService/CapturePacer 및 관련 엔진 테스트. 원인별 RED 후 최소 수정. UI와 모델 계약은 부모와 조율.
3. UI build: MainActivity/Ui/SetupWizard/SetupCoach 및 직접 UI 검사. 기본/고급 구조와 방식 범위 설명. 엔진 파일은 수정하지 않는다.
4. 부모: 통합 빌드와 구현 검증, 소스 동결. 별도 verifier Sol/high가 요구 사항과 실제 전체 검사를 독립 확인한다.
5. 부모: PC/휴대전화 APK를 15차에 납품. 연결된 PUVKID/PXE-Touch-Macro-Project의 공개 소스 구조를 확인해 코드/검사/변경 기록만 정상 커밋/푸시한다. 비밀 키/개인 프로필/개인 로그/빌드 캐시/전역 지침은 공개하지 않는다.

## 검증 환경과 시간
실제 사용자 블루스택과 매크로는 조작하지 않는다. 복사한 소유 PXE15 Android31 장치에서 검증한다. 기존 필수 검사 계획 총 720초/개별 제한 유지. 신규 검사 배치는 별도 제한을 명시하고 기존 검사와 중복 합산하지 않는다. 333ms 공식 AOSP 상수는 OS 구현 참고이며 블루스택에 동일 성능을 보장하는 근거가 아니다.

## 16:05 설계 확정 · 영역 인식 의미 보존

독립 검토와 엔진 분석 모두 기존 중심점 포함 기준에서 정확한 영역 자르기가 경계 글자를 소실시킴을 확인했다. 고정 여백은 모든 글자 경계 보존 근거가 없고 전체 화면 재시도는 새 중복 OCR 지연을 만든다. 따라서 선택적 ROI 제품 도입은 이번 범위에서 제외하며 전체 화면 OCR과 중심점 필터/같은 글자 순번/우선순위 캐시를 유지한다. ROI 제품은 수정0이고 crop 요구 검사는 실행 전 설계 초안이었다. 기존 검사의 기대값은 바꾸지 않는다. 신규 영역 검사는 기존 경계 중심/순번/우선순위 단일 캐시와 실제 좌표 보존을 검증한다. 이 결정은 입력 보정 또는 실패 은폐가 아니며 정확도 보존을 위한 최소 구현 범위 확정이다.

추가 검사는 tools/recognition-check-plan.json에 고정한다. 작은 화면 UI6은 기존 필수720초의 남은 시간 안에서 수행하고 새로운 UI3/인식5/영역3은 별도 총240초(90/150), 각 내부60/120초로 수행한다. 모든 장치는 소유 PXE15만 사용한다.

## 16:11 즉시 진입 선택의 실제 UI 노출

목록 rule.immediate는 저장 모델에는 있으나 UI에 없으므로 세부 설정에 인식 즉시 들어가기 선택을 추가한다. 기본 false/기존 저장값 유지, 켜면 재확인 생략의 정확도 차이를 안내한다. 새 UI 네 번째 검사는 기본값/취소/저장/다른 방식 보존을 검증하며 기존 세 검사 기대값은 그대로다. 신규 UI 배치 expected4로 확정하고 90/60초 상한과 집중검사 총240초를 유지한다.

## 수리12~13 · 의도된 캡처 시간 정책 검사 개정

독립검증46개 중45개가 통과하고 CaptureRecoveryTest 첫 메서드의 구정책4초/8초/8초 하한이 실패했다. 실제 진단 요청간격1163/2153/4664ms에서 첫4000ms 조건이 실패했으며 4캡처(2거절+실제OCR+새재확인)·1진입·45초완료·UI응답은 먼저 통과했다. 마지막4664ms에는 실제OCR 처리도 포함되어 고정5초상한을 임의로 추가하지 않는다.

이번 요청의 의도된 지연 개선에 따라 이 한 메서드의 시간 정책 기대값만 개정한다. 공식API31의333ms 제한에 여유를 둔 명세base500ms, API30의1000ms에 여유를 둔base1100ms에서 2배/4배/성공후2배 간격을 독립 도출한다. 실제 callback응답→다음요청의 최소1000/2000/1000ms(API31+) 또는2200/4400/2200ms(API30)를 확인한다. 제품의 현재 interval값을 정답으로 읽지 않는다. 기존45초완료·4캡처/1진입·쿨다운·중단·UI응답 단언과 같은 클래스의 다른두메서드는 유지한다. 결정론적 Pacer6개가 정확한 기본·후퇴·성공절반회복·최대12초를 검증하므로 옛 느린 정책도 검출한다.

‘기존 검사 기대값 유지’는 이 의도된 시간 정책 변경을 숨기기 위한 기계적4/8/8유지가 아니다. 변경 전후의 명세와 진단RED·독립FAIL을 보존하고, 이 한 성능 정책 단언의 명시 개정을 별도 독립 검토로 확인한다. 안전 경계·재확인·터치 횟수는 약화하지 않는다. 기존32통과를 재사용하지 않고 새 동결에서 전체52를 공유720초 내 직접 재실행하며 추가12는 별도240초 내 실행한다.
